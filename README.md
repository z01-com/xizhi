**逐浪羲之 v1.0.0** - 汉字之美，逐浪而来

专业的字体矢量设计工具，支持字体分析、字形导出、矢量编辑、字体合成。

## 功能特性

- **字形浏览**: 分析 TTF/OTF 字体，浏览和筛选字符
- **批量导出**: 导出 PNG/JPG/SVG/EPS 格式字形图片
- **字形编辑**: 矢量锚点编辑，支持画笔/橡皮工具
- **生产中心**: 骨架注入法合成新字体
- **字性处理**: 字体元数据编辑 (双语言支持)
- **工程保存**: 保存设计进度为 .z01 工程文件

### 1. 起手 - 分析字体

- 选择 TTF/OTF 字体文件

- Name 表编辑 (支持中英文)

## 软件协议 "UNLICENSED" 表示保留所有权利，非开源软件

问：为我遍历，我的软件中引用了MIT开源组件吗？我想收缩开源范围，转为商业软件，不想用MIT协议 ，推荐一个符合我的协议 。
答：
依赖协议扫描结果
运行时依赖（打包进 exe）
包名	协议	用途
react / react-dom	MIT	UI 框架
konva / react-konva	MIT	画布渲染
fontkit	MIT	字体解析
@napi-rs/canvas	MIT	图像处理
sql.js	MIT	数据库
iconv-lite	MIT	编码转换
zico	MIT	图标库
remixicon	Apache-2.0	图标库
开发依赖（不打包）
包名	协议
electron, vite, electron-builder, concurrently, wait-on	MIT
typescript	Apache-2.0

结论
MIT 协议不影响你转为商业软件。 MIT 是极其宽松的协议，明确允许商用、闭源、修改、再发布，唯一要求是保留原版权声明（通常放在软件"关于"或 LICENSE 文件中即可）。你不需要替换或移除任何依赖。

推荐：将你自己的软件协议从 MIT 改为
你当前 package.json 写的是 "license": "MIT"，这意味着你把自己的代码也以 MIT 开源了。要收紧为商业软件，改为：


"license": "UNLICENSED"
这表示"保留所有权利"，npm 不会将其视为开源包。然后在项目根目录放一份 EULA.txt（最终用户许可协议），核心条款：

## 开始



### 主功能选项卡

开始选项卡，应该是选择TTF/otf字体，同时有【字形分析】按钮，点击【字形分析】后，启动字形浏览器，对该字体进处理，包括：
1. 选定ttf\otf字体，分析该字体，并弹出大窗体，将该字体所拥有的字符uni码以形象、直观的形式展现出来。
2. 用户可以采用拖拽鼠标、ctrl点选、shift多选，选定glyphs，继而点击(且兼容右键菜单)【导出】】选择相应的格式(EPS\SVG\JPG\PNG)、文件大小：200*200、400*400、600*600、800*800、1000*1000、1200*1200、1800*1800、批量导出到特定的目录，文件名称采用中文名命名，便于检索，如我.png、你.png、他.png，
  
现有的字形浏览，不支持鼠标滑动选区多选、也不支持shift键多选，要加上。
导出eps，同时导出了svg、eps两种式，且eps文件不对，在Illustrator中打开为空。

view、open的按钮没有恢复 ，整个软件的view\open，参照@old/main.py设计，即“同时在[浏览]按钮边上加open与view功能,open以
win文件管理器打开当前目录 ,view则是以默认程序打开当前选择的文件(当选择仅为目录非文件时,隐藏view)。”
字形分析，导出字符后，即弹出当前字符所在目录 ，方便用户决策管理。
导出的EPS文件，垂直方向反了，需要以Y轴镜像翻转。
“浏览器底部有独立的本次操作历史，不混到其他选项卡记录里。”理解错了，不仅要有日志记录，还要一个历史记录选项框，贴着说
明写完了，便于下次操作。
字形浏览中，字体效果没有渲染，只显示宋体字效果，应该渲染出该字的实际效果。

### 日志控制台

隐藏主界面的“实时控制台/执行日志"，将其做成一个分离式窗口，默认不显示。
在主界面右下角，加一个图标 <i class="ri-bubble-chart-line"></i> 点击此图片，弹出“实时控制台/执行日志"，以长条的形式贴在主界面的下方，上有放大、缩小功能，放大则全屏显示，缩小则恢复隐藏，也可以手动拖拽更改大小、悬停位置。

### 软件换色-主题功能

主题换色功能
软件主界面，右上角'设置'后面增加横向椭圆分段式胶囊按钮，点击可以换色。
分别为：默认白、灰、红、黑，四个色系。
主题换色按钮，要求可以实现标题栏同时变色，横向椭圆分段式胶囊按钮不要汉字白、灰、红、黑，以不同的颜色表达即可，即按钮上无文字。

横向椭圆分段式胶选色囊按钮不要汉字白、灰、红、黑，以不同的颜色表达即可，不需要在里面加一个圆点，即直接渲染btn-group中子btn的背景。

## z01工程包讲解

本案中，设计器创建的`.z01`程序，应该包括这些信息：
1. 字符设计元素

### 复合轮廓填充

问题：字形设计界面有问题，对于09这样中间有多个形状组合的字体，当前在字形设计器中打开，会显示全黑，`(`这样的符号也在设计器中
  显示为半圆全黑，应该是渲染模式有问题，轮廓算法有问题，要纠正。

原因：已修复字形设计器的复合轮廓填充问题。

  问题原因：
  设计器之前把每条轮廓单独填充，0 / 9 / 8 这类“外轮廓 + 内轮廓”的字形，内轮廓无法参与镂空计算，所以会全黑；( 这类由边界  组合出来的轮廓也容易被错误填成块。

  修复方式：
  在 src/renderer/components/GlyphEditor.tsx 中改为：

  - 按颜色把轮廓合并成复合路径。
  - 用 fillRule="nonzero" 一次性填充复合路径。
  - 保留轮廓方向控制能力，也兼容你之前要求的“翻转轮廓方向”功能。

#### 问题一：Unexpected value for GlyphCount in gvar
问题一：导出彩色字体后，验证ttf文件失败，用fontcreator打开ttf提示：Unexpected value for GlyphCount in gvar
   已修复 FontCreator 报错 Unexpected value for GlyphCount in gvar 的根因。

  原因：
  源字体如果是变量字体，会带有 gvar/fvar/avar/HVAR/VVAR/MVAR 等变量字体表。发布彩色字体时我们会修改 glyf 并新增彩色图层

  已修复：

      - gvar
      - fvar
      - avar
      - HVAR
      - VVAR
      - MVAR
      - STAT

  - 发布后强校验：如果成品仍残留这些变量表，会直接报错，不再输出有结构隐患的字体。
  - 彩色表仍按模式正常生成：
      - COLR 模式：COLR + CPAL
      - SVG 固定色：SVG
      - SVG 色板：SVG  + CPAL
      - 全兼容：COLR + CPAL + SVG

#### 问题二：但字体位置不对，偏移了原来位于字体中心的位置

问题二：导出彩色字体成功，但字体位置不对，偏移了原来位于字体中心的位置，偏移到原字体最底边的下方了，请修正此BUG，这是我们软件对于黑白、彩色都有的BUG、还是仅对彩色字体的BUG，要全面彻查。

答：验证结果很关键：黑白 glyf 和 COLR 图层的字体坐标边界是正确的，glyf bbox 保持在原始位置；问题集中在 SVG 彩色表。当前
  SVG 表把字体坐标转换成 ascent - y，这会把基线体系变成从上往下的画布体系，FontCreator 这类工具会把它显示到基线下方。我
  要把 SVG 表改成 OpenType SVG 的基线坐标：y = -fontY，viewBox 使用 -ascent 到 -descent。

结论：

  - 黑白字体发布：坐标正确。
  - COLR 彩色字体发布：坐标正确，因为 COLR 图层仍走 glyf 字体坐标。

  - SVG 彩色字体坐标改为 OpenType SVG 基线坐标：
      - SVG path 的 Y 坐标改为 -fontY
      - SVG viewBox 改为：0 -ascent advance height
